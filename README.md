# tinvest-snapshot

Desktop-приложение и консольная утилита для Т-Инвестиций: снимок портфеля
(позиции, свободные деньги, доходности облигаций, ближайшие купоны/дивиденды),
выгрузка операций по всем счетам за период, а также поиск и фильтрация
инструментов на бирже Т-Инвест — в файлы **JSON, CSV и XLSX** с накоплением
истории запусков.

**GUI** — desktop-приложение на Fyne: четыре вкладки (портфель, операции,
инструменты, настройки), таблицы с сортировкой/фильтрацией/группировкой,
поиск инструментов по тикеру/названию/ISIN с фильтрами (для облигаций —
валюта, частота купона, уровень риска, месяц купона, тип купона, диапазон
ставки), карточка инструмента со ссылкой на сайт Т-Инвестиции, экспорт
отчётов и текущего вида в CSV/XLSX, автообновление по таймеру, русский и
английский интерфейс.

**CLI** — консольный режим: те же данные, те же форматы отчётов, работает
без графической среды (серверы, Cron). Оба режима используют одну кодовую
базу и один `config.json`.

Реализовано на Go через официальный REST-шлюз T-Invest API; GUI —
[Fyne v2.6.3](https://fyne.io/), XLSX —
[`github.com/xuri/excelize`](https://github.com/xuri/excelize) (чистый Go).
Итог — статические бинари без внешних runtime-зависимостей, доступны
для Linux и Windows (amd64).

Доходности облигаций (текущая доходность и YTM) T-Invest API не отдаёт
готовыми полями, поэтому они вычисляются из сырых данных (график купонов,
цена, номинал, НКД, дата погашения) в пакете `internal/bondyield`. YTM
считается только для облигаций с фиксированным купоном без амортизации и без
признака бессрочности; для флоатеров/амортизируемых/бессрочных облигаций, а
также при недостатке данных — `н/д`.

## GUI (desktop-приложение)

### Требования

- Токен T-Invest API **только на чтение** (создаётся в личном кабинете
  Т-Инвестиций). Приложение не выполняет торговых операций.
- **Linux:** X11 или Wayland (XWayland), библиотеки OpenGL (обычно уже
  установлены в desktop-дистрибутивах; для headless-сборки —
  `xorg-dev`/`libgl1-mesa-dev`). Бинарь статический, не требует установки
  Fyne или Go.
- **Windows:** Windows 10+, amd64. Бинарь включает всё необходимое (Go/Fyne
  runtime), не требует установки .NET, Java или других рантаймов.
- Для сборки из исходников — Go 1.25+, CGO (для GUI нужна графическая
  подсистема Fyne), на Linux — заголовки X11/OpenGL, на Windows-кросс-сборке —
  `x86_64-w64-mingw32-gcc` (см. [установку](docs/installation.md)).

### Запуск GUI

Готовый бинарь запускается без аргументов — конфиг ищется как `config.json`
рядом с бинарём:

```
./tinvest-gui-linux-amd64
```

На Windows — двойной клик по `tinvest-gui-windows-amd64.exe`.

Флаг `--config <путь>` указывает альтернативный файл конфигурации:
```
./tinvest-gui-linux-amd64 --config /home/user/tinvest-config.json
```

### Вкладки

| Вкладка | Назначение |
|---|---|
| **Портфель** | Позиции, свободные деньги, итоги по счетам и общий итог — по всем счетам пользователя. Кнопки «Обновить» и «Экспорт» (полный комплект: JSON + CSV портфеля + CSV операций + XLSX). |
| **Операции** | Список операций за период (сделки, комиссии, пополнения/выводы, купоны, дивиденды, налоги). Период задаётся полями «с»/«по»; при пустых полях — автоопределение начала периода как в CLI. Кнопки «Обновить» и «Экспорт» (текущий вид таблицы в CSV + XLSX). |
| **Инструменты** | Поиск инструментов на бирже Т-Инвест: выбор типа (акции/облигации/ETF/валюты/фьючерсы), строка поиска по тикеру/названию/ISIN, фильтры. Результаты — в таблице с сортировкой, фильтрацией, группировкой. Кнопка «Экспорт» сохраняет текущий вид в CSV + XLSX. |
| **Настройки** | Режим API, источник токена, каталог отчётов, целевая валюта, повторы, автообновление, срок кэша справочника, язык интерфейса, часовой пояс. Изменения сохраняются в `config.json` и применяются сразу. |

### Таблицы: сортировка, фильтрация, группировка, поиск

Все таблицы GUI (портфель, операции, инструменты) поддерживают:

- **Сортировка:** клик по заголовку колонки — по возрастанию; повторный
  клик — по убыванию. Активная колонка помечена стрелкой ▲/▼.
- **Фильтрация по колонке:** выбор колонки в выпадающем списке «Фильтр»
  и ввод значения. Остаются только строки, содержащие подстроку в выбранной
  колонке (регистронезависимо). Очистка значения возвращает полный список.
- **Группировка:** выбор колонки в выпадающем списке «Группировать по».
  Строки группируются по значению выбранной колонки. Группы можно сворачивать
  и разворачивать кликом по заголовку группы (▾/▸).
- **Текстовый поиск:** поиск по всей таблице. Кнопка «Найти далее»
  переходит к следующему совпадению с подсветкой строки.

### Карточка инструмента и ссылка на сайт

- **Левый клик** по строке с инструментом в любой таблице открывает диалог
  с полями инструмента. Для облигаций — включая номинал, дату погашения,
  амортизацию, оферты; для акций — данные о дивидендах.
- Если доступен тикер или FIGI — в диалоге отображается ссылка
  **«Открыть на сайте Т-Инвестиции»**, ведущая на страницу инструмента
  на `tbank.ru`.
- **Правый клик** по ячейке таблицы → «Копировать значение» — копирует
  содержимое ячейки в буфер обмена.

### Поиск и фильтрация инструментов

На вкладке «Инструменты» доступны фильтры:

| Фильтр | Применяется к типам | Описание |
|---|---|---|
| Тип инструмента | все | Акции, облигации, ETF, валюты, фьючерсы |
| Поиск | все | Поиск по тикеру, названию и ISIN (регистронезависимо, по подстроке) |
| Валюта | все | Валюта номинала |
| Биржа | все | Биржа/площадка |
| Сектор | все | Сектор (где применимо) |
| Уровень риска | облигации | Низкий/средний/высокий/н/д (уровень риска T-Invest) |
| Частота купона | облигации | Раз в месяц / квартал / полгода / год |
| Тип купона | облигации | Фиксированный / флоатер |
| Ставка купона | облигации | Диапазон «от» и/или «до» в % годовых |
| Месяц купона | облигации | Месяц ближайшего купона |
| Дивиденды | акции | Наличие дивидендных выплат за последние 12 месяцев |

Все фильтры комбинируются (логическое И). Результаты отображаются в таблице,
доступны сортировка, фильтрация по колонке и группировка.

### Кэш справочника

Справочник инструментов загружается с API при первом поиске и сохраняется
локально. При последующих запусках используется кэш, пока он не устареет
(срок задаётся в настройках, по умолчанию 24 часа). Кнопка «Обновить»
на вкладке инструментов принудительно перезагружает справочник.
Время последнего обновления отображается под кнопкой поиска.

### Автообновление

Данные портфеля и операций автоматически обновляются с заданным интервалом
(настраивается в минутах; 0 — автообновление отключено). Также работает
ручное обновление по кнопке «Обновить» на вкладках портфеля и операций.

### Экспорт

- **Портфель:** кнопка «Экспорт» — полный комплект отчётов (JSON, CSV
  портфеля, CSV операций, XLSX) в выбранный каталог. Именование и
  неперезапись файлов — как в CLI.
- **Операции и Инструменты:** кнопка «Экспорт» — текущий вид таблицы
  (с применёнными фильтрами, сортировкой и группировкой) в CSV и XLSX.
  Диалог сохранения предлагает имя по умолчанию `table_<дата>_<время>.csv`.

### Часовой пояс

Время операций и дата обновления справочника отображаются в часовом поясе,
заданном в настройках (UTC±N). По умолчанию — UTC+4.

### Язык интерфейса

Русский (по умолчанию) и английский. Переключение в настройках, без
пересборки. Тексты вынесены в JSON-файлы (`cmd/gui/i18n/ru.json`,
`cmd/gui/i18n/en.json`); добавление нового языка — добавление файла
перевода без изменения кода.

## Установка

### Сборка GUI

Собрать GUI из исходников (Linux, требуется Go 1.25+, CGO и заголовки X11/OpenGL):

```
git clone https://github.com/svdmitrij/tinvest-snapshot.git
cd tinvest-snapshot

go build -o tinvest-gui -tags ci ./cmd/gui
```

Кросс-сборка GUI под Linux и Windows (результат — в `dist/`):

```
./scripts/build-gui.sh          # Linux + Windows
./scripts/build-gui.sh linux    # только Linux
./scripts/build-gui.sh windows  # только Windows
```

Для сборки под Windows нужен `x86_64-w64-mingw32-gcc` (пакет `mingw-w64`).
Подробнее — в [инструкции по установке](docs/installation.md).

### Сборка CLI

Собрать CLI из исходников:

```
git clone https://github.com/svdmitrij/tinvest-snapshot.git
cd tinvest-snapshot

go build -o tinvest-snapshot ./cmd/snapshot   # бинарь под текущую платформу
```

Либо кросс-сборка под Linux и Windows одной командой (результат — в `dist/`):

```
./scripts/build.sh
```

Либо готовые версионированные архивы с контрольными суммами (для публикации
релиза): `./scripts/package.sh v1.4.0` — соберёт
`dist/tinvest-snapshot-v1.4.0-linux-amd64.tar.gz`,
`dist/tinvest-snapshot-v1.4.0-windows-amd64.zip` (или `.tar.gz`, если `zip`
недоступен в системе) и `dist/SHA256SUMS.txt`. Внутри каждого архива —
бинарь CLI, `config.example.json` и этот `README.md`.

## Конфигурация

GUI и CLI используют один и тот же `config.json`. Скопируйте
`config.example.json` в `config.json` рядом с бинарём и заполните:

```json
{
  "mode": "sandbox",
  "token": "",
  "token_env": "TINVEST_TOKEN",
  "retries": 3,
  "retry_delay_ms": 1000,
  "reports_dir": "reports",
  "target_currency": "",
  "endpoint": "",
  "app_name": "tinvest-snapshot",
  "auto_refresh_minutes": 0,
  "catalog_ttl_hours": 24,
  "language": "ru",
  "timezone_offset": 4
}
```

| Параметр | Тип | Значение по умолчанию | За что отвечает |
|---|---|---|---|
| `mode` | строка | `sandbox` (если поле пустое) | Режим API: `prod` (боевой контур) или `sandbox` (песочница). |
| `token` | строка | `""` | Токен API напрямую в конфиге. Не рекомендуется — используйте `token_env`. Никогда не пишется в логи, вывод или отчёты. |
| `token_env` | строка | `TINVEST_TOKEN` (если `token` и `token_env` оба пусты) | Имя переменной окружения, из которой читается токен. Приоритет выше, чем у `token`. |
| `retries` | число | `3` (значения `< 0` приводятся к `0`) | Число дополнительных попыток при временных ошибках API. |
| `retry_delay_ms` | число, мс | `1000` | Базовая задержка между попытками; растёт линейно. |
| `reports_dir` | строка | каталог `reports` рядом с бинарём | Каталог для JSON/CSV/XLSX-отчётов. Создаётся автоматически. |
| `target_currency` | строка | `""` (пересчёт выключен) | Валюта пересчёта итогов (например, `usd`). |
| `endpoint` | строка | `""` (официальный URL для выбранного `mode`) | Переопределение базового URL API. |
| `app_name` | строка | `tinvest-snapshot` | Заголовок `x-app-name` для аналитики API. |
| `auto_refresh_minutes` | число | `0` (автообновление отключено) | **Только GUI:** интервал автообновления портфеля и операций в минутах. |
| `catalog_ttl_hours` | число | `24` | **Только GUI:** срок жизни кэша справочника инструментов в часах. |
| `language` | строка | `ru` | **Только GUI:** язык интерфейса — `ru` (русский) или `en` (английский). |
| `timezone_offset` | число, UTC±N | `4` (если поле отсутствует) | **Только GUI:** часовой пояс для отображения времени операций и обновления справочника. Допустимые значения: от −23 до +23. |

## Запуск (CLI)

```
export TINVEST_TOKEN=<ваш токен только на чтение>
./tinvest-snapshot --config config.json
```

Флаги командной строки (все необязательные):

| Флаг | Назначение |
|---|---|
| `--config <путь>` | путь к JSON-конфигу (по умолчанию `config.json`) |
| `--target-currency <код>` | пересчитать итоги в указанную валюту (например, `usd`), переопределяет `target_currency` из конфига |
| `--mode <prod\|sandbox>` | переопределить режим из конфига |
| `--from <ГГГГ-ММ-ДД>` | начальная дата выгрузки операций (с 00:00). Имеет приоритет над автоопределением по каталогу отчётов |
| `--to <ГГГГ-ММ-ДД>` | конечная дата выгрузки операций включительно (по 23:59:59). По умолчанию — момент запуска |

Начальная дата операций определяется в порядке приоритета: `--from` →
автоопределение (00:00 даты самого позднего файла `portfolio_*`/`operations_*`
в каталоге отчётов, день включительно) → дата открытия каждого счёта. Неверный
формат даты или `--from` позже `--to` — ошибка конфигурации (код выхода 2, без
обращения к API). Возможные дубли операций на стыке соседних выгрузок не
дедуплицируются.

Примеры:

```
./tinvest-snapshot --config config.json --target-currency usd
./tinvest-snapshot --config config.json --mode prod
./tinvest-snapshot --config config.json --from 2026-01-01 --to 2026-03-31
```

Коды выхода:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | не удалось получить или сохранить данные — после исчерпания всех попыток (`retries + 1`) |
| `2` | ошибка конфигурации или токена (до обращения к API) |

## Проверка работоспособности

1. Запустите утилиту с `mode: prod` (или `--mode prod`) на счёте с хотя бы
   одной позицией.
2. В консоли должна появиться сводка вида:
   ```
   Режим: prod. Получение данных из T-Invest API...

   === Сводка ===
   Счетов обработано: 2
   Суммарная стоимость:
     123456.78 RUB
   Операций выгружено: 42
   Период операций: 2026-01-01T00:00:00Z — 2026-07-09T09:00:00Z
   Файлы:
     reports/portfolio_20260709_120000.json
     reports/portfolio_20260709_120000.csv
     reports/operations_20260709_120000.csv
     reports/portfolio_20260709_120000.xlsx
   ```
3. Убедитесь, что в каталоге `reports_dir` появился новый комплект из
   четырёх файлов с общей меткой времени — предыдущие запуски при этом не
   перезаписываются (при совпадении секунды к имени добавляется `_1`,
   `_2` и т. д.).
4. Проверьте, что токен нигде не отображается: ни в консольном выводе, ни в
   содержимом любого из четырёх файлов.
5. Повторный запуск с флагом `--target-currency usd` должен добавить в JSON
   поля `total_converted` / `grand_total_converted` и строку
   `≈ ... USD (пересчёт)` в консольной сводке. Поле `rate` (использованный
   курс) есть у `total_converted` каждого счёта; у `grand_total_converted`
   оно появляется, только если общий итог пересчитан из одной исходной
   валюты — при нескольких валютах единого курса не существует, и поле
   опускается.

## Формат отчётов

Каждый запуск создаёт **четыре файла** с общей меткой времени
`<ГГГГММДД>_<ЧЧММСС>` (при совпадении секунды к имени добавляется `_1`, `_2`
и т. д.), не перезаписывая файлы предыдущих запусков:

| Файл | Содержимое |
|---|---|
| `portfolio_<штамп>.json` | снимок портфеля **и** операции — одним объектом |
| `portfolio_<штамп>.csv` | снимок портфеля (формат не изменился) |
| `operations_<штамп>.csv` | операции за период |
| `portfolio_<штамп>.xlsx` | лист «Портфель» + лист «Операции» — построчно эквивалентны CSV-файлам |

JSON — один объект `Snapshot`: `generated_at` (UTC, RFC3339), `mode`,
`accounts[]` (по каждому счёту — `positions[]`, `cash[]`, `total`,
опционально `total_converted`), `grand_totals[]`, опционально
`grand_total_converted`, а также `operations_period` (`from`/`to` —
фактические границы выгрузки, UTC RFC3339) и `operations[]`.

- Свободные деньги (`cash[]`) — **одна запись на валюту** на счёте (суммируются, если валюта встречается в портфеле несколько раз).
- Для облигаций (`positions[].bond`): `coupon_rate_pct`, `current_yield`,
  `yield_to_maturity`, `coupon_frequency`, `next_coupon_date`,
  `next_coupon_amount`, `issuer_rating`. Любое из полей — `н/д`, если
  исходных данных недостаточно.
- Для акций (`positions[].share`): `last_dividend_amount`, `frequency`
  (число выплат за последние 12 месяцев), `next_payment_date`,
  `next_payment_amount`. Если ближайшая выплата ещё не объявлена —
  `н/д`.

Портфельный CSV (`portfolio_*.csv`) — построчный вариант снимка.
`record_type` в первой колонке определяет смысл строки: `position`, `cash`,
`account_total`, `grand_total`; остальные колонки заполняются по смыслу
(денежные и специфичные для облигаций/акций колонки пустые там, где
неприменимы).

Каждая операция (`operations[]` в JSON, строки `operations_*.csv`, лист
«Операции» в XLSX) содержит поля:

| Поле (JSON / колонка CSV) | Значение |
|---|---|
| `id` / `operation_id` | идентификатор операции |
| `account_id`, `account_name` | счёт |
| `datetime` | дата и время операции (UTC, RFC3339) |
| `type` | тип операции, человекочитаемо (сделка, комиссия, пополнение/вывод, купон, дивиденд, налог и т. д.) |
| `instrument_type` | тип инструмента (пусто, если операция не связана с инструментом) |
| `ticker`, `isin`, `name` | инструмент (пусто, если операция не связана с инструментом) |
| `quantity` | количество (если применимо) |
| `payment_amount`, `payment_currency` | сумма операции и её валюта |
| `state` | статус операции: `исполнена`, `отменена`, `в процессе`, иначе `н/д` |

Выгружаются все типы операций, которые отдаёт API, без фильтрации; суммы
операций приводятся в валюте самой операции и в `target_currency` не
пересчитываются. За период выгружается вся история независимо от объёма
(используется постраничная выборка API по курсору).

## Типовые проблемы

### Общие (CLI и GUI)

**`Ошибка конфигурации: ...`.** Файл конфига не найден, не парсится как JSON,
указан недопустимый `mode`, либо не задан ни `token`, ни `token_env` —
проверьте `config.json`.

**Переменная окружения с токеном пуста.** Не выставлена переменная из
`token_env` (по умолчанию `TINVEST_TOKEN`), и `token` в конфиге тоже пуст.
Выполните `export TINVEST_TOKEN=...` перед запуском.

**Ошибки API/сети.** При временных сбоях утилита повторяет запрос согласно
`retries` и `retry_delay_ms`. GUI показывает ошибку в диалоге с возможностью
повторить операцию; CLI завершается с кодом 1 и сообщением в stderr. При
частых сбоях увеличьте `retries` и/или `retry_delay_ms`.

**`mode: sandbox` возвращает HTTP 500.** Известное ограничение тестового
окружения T-Invest API. Для реальной проверки используйте `mode: prod`
с токеном только на чтение.

**Поля облигации/акции — `н/д`.** Отсутствие данных в ответе API (например,
у бессрочной или амортизируемой облигации YTM принципиально не считается)
либо кратковременная ошибка при обогащении справочными данными.

### GUI

**Приложение не запускается (Linux): «cannot open display».** GUI требует
графическую сессию X11 или Wayland (XWayland). На headless-сервере запускайте
CLI-версию (`./tinvest-snapshot`).

**Окно не помещается на экране.** Приложение автоматически подстраивает
размер под физическое разрешение дисплея (читает `/sys/class/drm` на Linux).
Минимальное окно — 640×480; содержимое вкладок прокручивается, если окно
меньше.

**Не отображаются результаты поиска инструментов.** При первом запуске
справочник загружается с API (может занять несколько секунд). Дождитесь
сообщения «Справочник обновлён» в строке статуса вкладки «Инструменты».

**Данные не обновляются автоматически.** Проверьте `auto_refresh_minutes`
в настройках: значение 0 отключает автообновление. Задайте положительное
число (например, 5) и сохраните настройки.

**CLI**

**`Ошибка конфигурации: неверный формат --from "...": ожидается ГГГГ-ММ-ДД`**
**или `--from (...) позже --to (...)` (код 2).** Проверьте формат дат
(`--from 2026-01-01`, не `01.01.2026`) и что `--from` не позже `--to`.
