# tinvest-snapshot

Консольная утилита: снимок всех счетов в Т-Инвестициях (позиции, свободные
деньги, доходности облигаций, ближайшие купоны/дивиденды) в файлы **JSON и
CSV** с накоплением истории запусков — каждый запуск пишет новую пару файлов,
ничего не перезаписывая.

Реализована на чистой стандартной библиотеке Go через официальный REST-шлюз
T-Invest API — единый статический бинарь без внешних runtime-зависимостей,
доступен для Linux и Windows (amd64).

Доходности облигаций (текущая доходность и YTM) T-Invest API не отдаёт
готовыми полями, поэтому они вычисляются из сырых данных (график купонов,
цена, номинал, НКД, дата погашения) в пакете `internal/bondyield`. YTM
считается только для облигаций с фиксированным купоном без амортизации и без
признака бессрочности; для флоатеров/амортизируемых/бессрочных облигаций, а
также при недостатке данных — `н/д`.

## Требования

- Токен T-Invest API **только на чтение** (создаётся в личном кабинете
  Т-Инвестиций). Утилита не выполняет торговых операций.
- Для сборки из исходников — Go 1.25+. Для запуска готового бинаря — ничего,
  кроме самой ОС (Linux amd64 или Windows amd64): бинарь статический,
  сторонних зависимостей не требует.

## Установка

Собрать из исходников:

```
git clone https://github.com/svdmitrij/tinvest-snapshot.git
cd tinvest-snapshot
git checkout v1.2.0          # актуальный релиз; можно опустить, чтобы остаться на master

go build -o tinvest-snapshot ./cmd/snapshot   # бинарь под текущую платформу
```

Либо кросс-сборка под Linux и Windows одной командой (результат — в `dist/`):

```
./scripts/build.sh
```

Либо готовые версионированные архивы с контрольными суммами (для публикации
релиза): `./scripts/package.sh v1.2.0` — соберёт
`dist/tinvest-snapshot-v1.2.0-linux-amd64.tar.gz`,
`dist/tinvest-snapshot-v1.2.0-windows-amd64.zip` (или `.tar.gz`, если `zip`
недоступен в системе) и `dist/SHA256SUMS.txt`. Внутри каждого архива —
бинарь, `config.example.json` и этот `README.md`.

## Конфигурация

Скопируйте `config.example.json` в `config.json` рядом с бинарём и
заполните:

```json
{
  "mode": "sandbox",
  "token": "",
  "token_env": "TINVEST_TOKEN",
  "retries": 3,
  "retry_delay_ms": 1000,
  "reports_dir": "reports",
  "target_currency": "",
  "endpoint": "",
  "app_name": "tinvest-snapshot"
}
```

| Параметр | Тип | Значение по умолчанию | За что отвечает |
|---|---|---|---|
| `mode` | строка | `sandbox` (если поле пустое) | Режим API: `prod` (боевой контур) или `sandbox` (песочница). Переопределяется флагом `--mode`. |
| `token` | строка | `""` | Токен API напрямую в конфиге. Не рекомендуется — используйте `token_env`. Никогда не пишется в логи, вывод или отчёты. |
| `token_env` | строка | `TINVEST_TOKEN` (если `token` и `token_env` оба пусты) | Имя переменной окружения, из которой читается токен. Приоритет выше, чем у `token`. |
| `retries` | число | `3` (значения `< 0` приводятся к `0`) | Число дополнительных попыток при временных ошибках API (сеть, HTTP-ошибки). Итого запросов — `retries + 1`. |
| `retry_delay_ms` | число, мс | `1000` (используется и при `<= 0`) | Базовая задержка между попытками; растёт линейно (`delay × номер попытки`). |
| `reports_dir` | строка | каталог `reports` рядом с бинарём | Каталог, куда пишутся JSON/CSV-отчёты. Создаётся автоматически, если не существует. |
| `target_currency` | строка | `""` (пересчёт выключен) | Валюта пересчёта итогов по умолчанию (например, `usd`). Переопределяется флагом `--target-currency`. |
| `endpoint` | строка | `""` (используется официальный URL для выбранного `mode`) | Переопределение базового URL API — для тестового/альтернативного шлюза. |
| `app_name` | строка | `tinvest-snapshot` | Значение заголовка `x-app-name`, передаётся в T-Invest API для аналитики по приложениям. |

## Запуск

```
export TINVEST_TOKEN=<ваш токен только на чтение>
./tinvest-snapshot --config config.json
```

Флаги командной строки (все необязательные):

| Флаг | Назначение |
|---|---|
| `--config <путь>` | путь к JSON-конфигу (по умолчанию `config.json`) |
| `--target-currency <код>` | пересчитать итоги в указанную валюту (например, `usd`), переопределяет `target_currency` из конфига |
| `--mode <prod\|sandbox>` | переопределить режим из конфига |

Примеры:

```
./tinvest-snapshot --config config.json --target-currency usd
./tinvest-snapshot --config config.json --mode prod
```

Коды выхода:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | не удалось получить или сохранить данные — после исчерпания всех попыток (`retries + 1`) |
| `2` | ошибка конфигурации или токена (до обращения к API) |

## Проверка работоспособности

1. Запустите утилиту с `mode: prod` (или `--mode prod`) на счёте с хотя бы
   одной позицией.
2. В консоли должна появиться сводка вида:
   ```
   Режим: prod. Получение данных из T-Invest API...

   === Сводка ===
   Счетов обработано: 2
   Суммарная стоимость:
     123456.78 RUB
   Файлы:
     reports/portfolio_20260709_120000.json
     reports/portfolio_20260709_120000.csv
   ```
3. Убедитесь, что в каталоге `reports_dir` появилась новая пара файлов
   `portfolio_<ГГГГММДД>_<ЧЧММСС>.json` / `.csv` — предыдущие запуски при этом
   не перезаписываются (при совпадении секунды к имени добавляется `_1`,
   `_2` и т. д.).
4. Проверьте, что токен нигде не отображается: ни в консольном выводе, ни в
   содержимом JSON/CSV.
5. Повторный запуск с флагом `--target-currency usd` должен добавить в JSON
   поля `total_converted` / `grand_total_converted` (с полем `rate` —
   использованным курсом) и строку `≈ ... USD (пересчёт)` в консольной
   сводке.

## Формат отчётов

JSON — один объект `Snapshot`: `generated_at` (UTC, RFC3339), `mode`,
`accounts[]` (по каждому счёту — `positions[]`, `cash[]`, `total`,
опционально `total_converted`), `grand_totals[]` и опционально
`grand_total_converted`.

- Свободные деньги (`cash[]`) — **одна запись на валюту** на счёте (суммируются, если валюта встречается в портфеле несколько раз).
- Для облигаций (`positions[].bond`): `coupon_rate_pct`, `current_yield`,
  `yield_to_maturity`, `coupon_frequency`, `next_coupon_date`,
  `next_coupon_amount`, `issuer_rating`. Любое из полей — `н/д`, если
  исходных данных недостаточно.
- Для акций (`positions[].share`): `last_dividend_amount`, `frequency`
  (число выплат за последние 12 месяцев), `next_payment_date`,
  `next_payment_amount`. Если ближайшая выплата ещё не объявлена —
  `н/д`.

CSV — построчный вариант того же снимка, по одному файлу на запуск.
`record_type` в первой колонке определяет смысл строки: `position`, `cash`,
`account_total`, `grand_total`; остальные колонки заполняются по смыслу
(денежные и специфичные для облигаций/акций колонки пустые там, где
неприменимы).

## Типовые проблемы

**`Ошибка конфигурации: ...` (код выхода 2).** Файл конфига не найден, не
парсится как JSON, указан недопустимый `mode`, либо не задан ни `token`, ни
`token_env` — проверьте `config.json`.

**`Ошибка: переменная окружения ... пуста и inline-токен не задан` (код 2).**
Не выставлена переменная окружения из `token_env` (по умолчанию
`TINVEST_TOKEN`), и `token` в конфиге тоже пуст. Выполните
`export TINVEST_TOKEN=...` перед запуском.

**`Не удалось получить снимок портфеля: ... исчерпаны попытки (N) ...` (код 1).**
API вернуло ошибку на всех попытках (`retries + 1`). Стандартный вывод в
stderr во время выполнения логирует каждую неудачную попытку — по нему видно
конкретный HTTP-код и сервис/метод, на которых происходит сбой. При
частых сбоях увеличьте `retries` и/или `retry_delay_ms` в конфиге.

**`mode: sandbox` возвращает HTTP 500 на все запросы.** Известное ограничение
внешнего тестового окружения T-Invest API, а не дефект утилиты: код песочницы
идентичен боевому пути и покрыт юнит-тестами. Для реальной проверки
используйте `mode: prod` с токеном только на чтение.

**Поля облигации/акции — `н/д`.** Означает отсутствие данных в ответе API
(например, у бессрочной или амортизируемой облигации YTM принципиально не
считается) либо кратковременную ошибку при обогащении справочными данными —
в этом случае сама позиция всё равно попадает в отчёт, ошибка логируется в
stderr, но не прерывает выполнение.
